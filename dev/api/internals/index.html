Internals

These names are not exported. Reach them as GeometricSolvers.name.

The storage seam

The storage seam lets an algorithm read each function's result rather than the storage itself, so the storage-specific operations stay at the leaves. Each function has a value method for a StaticArray or a Number iterate (R1) and an in-place method for an AbstractArray buffer slot (R3).

GeometricSolvers.buffer — Function
buffer(x)
buffer(x, TF, dims...)

One storage slot for an iterate like x, in the element type TF and with the shape dims. A caller creates slots during initialization; an algorithm consumes their returned values.

A value iterate — a StaticArray or a Number — has no slot: the call returns nothing, so the R1 state carries no buffer and spends no register on one. A static matrix is never an iterate and gets no slot either, which is why this method is written on StaticArray and not on StaticVector. An array iterate allocates a storage slot via similar.

source
GeometricSolvers.residual!! — Function
residual!!(y, prob, x, p)

The residual F(x, p) of prob at the iterate x, for the parameters p, in the storage of y, and return it.

y is the storage slot the residual is to occupy, and it alone selects the call form of the problem's F: with no buffer slot (nothing) the call is F(x, p), for an SVector, an MVector, a Number and an Array alike, because the iterate's type is read nowhere; with an array buffer slot y the call is F(y, x, p). There is no inplace flag that could disagree with the iterate, and no hasmethod.

source
residual!!(F_out, prob::BatchEliminated, x, p; repeat_same_tol = false) -> F_out

The outer residual of the reduced-space elimination at the field x: solve the batch from the warm start prob.Y at the inner tolerance of this evaluation, deposit its moments, and write g_2(x). Every call records its (‖g₁‖, ‖g₂(prev)‖) in prob.g₁_history and prob.g₂_prev_history and its eliminated set in prob.eliminated_index_log, and leaves the batch at the root of the system it solved, which the next evaluation warm-starts from. A batch whose systems did not all converge, with a residual above 32 eps(R_in) √N_p, has no value to report: the residual it writes is NaN, so no outer step accepts it. With repeat_same_tol = true it re-uses the tolerance of the previous evaluation instead of the schedule of BatchEliminated, so a second evaluation at the same x stops every system at 0 iterations. The outer iterate's length must be the length of the problem's field: any other is a DimensionMismatch.

GeometricSolvers.regularize!! — Function
regularize!!(J, μ)

Add μ * I to the Jacobian J in its storage, and return it — on a rectangular J, to the min(M, N) entries of its leading diagonal. When iszero(μ) holds, J is returned untouched. On a Matrix the diagonal is shifted in a loop so bounds-checked runs allocate nothing; on any other AbstractMatrix the diagonal view view(J, diagind(J)) is updated by broadcast so device arrays perform no scalar indexing. An SMatrix has immutable entries, so its shifted diagonal is a rebuilt tuple.

The solver loop and its helpers

A nonlinear method enters the loop of solve!! through init_state, which builds its state, step!!, and the two hooks start!! and finish!!, which run once before the first step and at every return. residual_buffer names the slot of the state that holds F(x₀), and refine!! refines the linear direction d in working precision before globalization; gmres_ir!! is the GMRES-IR stage that follows a failed pass of a GMRESRefinement.

GeometricSolvers.init_state — Function
init_state(method, prob::AbstractNonlinearProblem, x, p)

Build the state of method for AbstractNonlinearProblem prob at the initial iterate x and parameters p: its workspace, its AD preparation and its rule state, in one concrete type per method. In R1 (SVector, MVector or Number), init_state is allocation-free and returns an isbits state when prob and method are isbits.

GeometricSolvers.residual_buffer — Function
residual_buffer(state)

The slot that solve!! evaluates F(x₀) into: the residual workspace of state for an array iterate, and nothing for a value iterate. The default is nothing, which lets residual!! return a new value.

source
GeometricSolvers.step!! — Function
step!!(state, method, prob::AbstractNonlinearProblem, x, Fx, p)

Compute one nonlinear solver step from (x, Fx) and return (x₊, F₊, state₊, info) where info is a StepInfo. A line-search step of Newton or Picard reads the anchor merit that the last start!! or step!! on its state set, so it takes only the (x, Fx) that they returned; on a state that no start!! saw, or that solve!! returned, it returns NONFINITE and keeps x and Fx.

source
GeometricSolvers.start!! — Function
start!!(state, method, prob::AbstractNonlinearProblem, x, Fx, p, fnorm₀) -> state

Prepare state for a solve from x, with residual Fx and its norm fnorm₀, and return the state that the first step reads. solve!! calls it once, before its stopping test at 0 iterations, so a state reused across solves starts each solve afresh. The default returns state. Newton resets its rule state, and Newton and Picard set the anchor merit norm2(Fx) of a line search, which init_state leaves at NaN.

source
GeometricSolvers.finish!! — Function
finish!!(state, method, prob::AbstractNonlinearProblem, x, Fx, status) -> (x, status, state)

Close a solve that ends at x, with residual Fx and status, and return the triple that solve!! returns. solve!! calls it at every return. The default returns (x, status, state). A method may return another iterate; it then sets status.fnorm itself, and for an array iterate it writes that iterate into x and returns x. Newton and Picard set the anchor merit of a line search to NaN again, as init_state does.

source
GeometricSolvers.refine!! — Function
refine!!(d, ref, fac, jvpprep, prob, x, Fx, fnorm, p, refbuf = nothing) -> (d, failed::Bool)

Refine the initial linear direction d for J(x) d = -F(x) using the factor fac and the JVP preparation jvpprep. With NoRefinement, returns (d, false) and reads neither fnorm nor Fx. With Refinement or the LU-IR passes of GMRESRefinement, performs up to ref.maxiter defect-correction steps in working precision T and returns (d_best, failed), where failed is true if a step does not strictly reduce ‖F(x) + J(x) d‖ or if ref.maxiter iterations finish above max(ref.η, √eps(real(T))) * fnorm; the GMRES-IR stage of a GMRESRefinement follows a failed pass in the step, not here. fnorm is ‖F(x)‖ when the caller already holds it and nothing otherwise, in which case this method forms it from Fx.

source
GeometricSolvers.sync_merit — Function
sync_merit(state, method, merit::Real)

Update a started line-search member state's stored baseline merit $\phi(x) = \|F(x)\|_2^2$ to merit when another member has moved the iterate (x, Fx) since state's last step. Preserves NaN on an un-started state so calling step!! without start!! still fails closed with NONFINITE, and leaves the merit of a Static or DogLeg state (merit === nothing) as it is. A Newton state also sets the residual norm it carries to NaN, so that its next step measures $\|F(x)\|$ of the residual it is given.

GeometricSolvers.init_globalization — Function
init_globalization(g, x)
init_globalization(g, linsolve, x)

Allocate the workspace named tuple for globalization method g at iterate x through buffer(x): (; xt, Ft) for Static, (; xt, Ft, Jv) for a LineSearch, (; g̃, ĝ, Jg, s, xt, Ft, u, b) for DogLeg, whose u and b share the storage of s and Jg for a square problem, and (; Jδ, xt, Ft, R₀, c₀, R, c, d_diag, w) for LevenbergMarquardt, whose stacked slots R₀ to w are nothing where the step reads the SVD factor and not the stacked solve. In R1 every slot is nothing; in R3 each slot is a preallocated array like x. The method with linsolve is the one Newton calls; it takes the linear method of the solve into account, and for any g but LevenbergMarquardt it is the method without it.

GeometricSolvers.LineFunction — Type
LineFunction(prob, x, Fx, d, p, jvpprep, xt = nothing, Ft = nothing, Jv = nothing)

The line function along the ray from x in the direction d for AbstractNonlinearProblem prob with parameters p, Jacobian-vector preparation jvpprep, and workspace slots xt, Ft and Jv; Fx is the residual at x. It is a callable struct, not a subtype of Function, so isbits holds when its fields are isbits.

φ(lf, α) advances x along d by α through update_iterate!!, evaluates the residual through residual!!, and returns its merit norm2, $\|F\|_2^2$. φ′(lf, α) evaluates the derivative of the merit, $2\,\mathrm{Re}\langle F, J d\rangle$, through jvp!! and rdot. A line search along lf returns the residual at its step in its LineSearchResult, and Fx for a step it did not evaluate. Calling lf(α) delegates to φ(lf, α).

source
GeometricSolvers.globalize!! — Function
globalize!!(g, ls, prob, x, Fx, d, p, jvpprep, stepkind = MeasuredSlope())

Advance x along d under the globalization method ls using workspace g and return (x₊, F₊, g, info) where info is a StepInfo.

For Static, globalize!! takes the fixed step ls.α through update_iterate!! and evaluates residual!! once, without a line-search loop. When the step d or the new residual norm is not finite, it returns (x, Fx, g, StepInfo{R}(NONFINITE, rnorm(Fx), abs(ls.α) * rnorm(d), 0, false, false)) without advancing the iterate or evaluating F at a non-finite trial point.

For Backtracking, Bisection and StrongWolfe, globalize!! returns NONFINITE immediately when rnorm(d) is not finite; otherwise it builds a LineFunction and calls linesearch from α = 1. An accepted step returns the residual that the search evaluated at res.α, so it costs no further evaluation of F. A LINESEARCH_FAILED result whose φ is finite and strictly less than φ₀ = norm2(Fx) takes the step res.α and reports failures = 1; otherwise the iterate stays at x with stepnorm = 0.

source
GeometricSolvers.LineSearch — Type
LineSearch{R}

The supertype of the line searches Static, Backtracking, Bisection and StrongWolfe, whose numbers are of the real type R. A line search is a method: it is isbits, it holds numbers and, except Static, an Int32 cap and nothing else, and linesearch runs it.

Every line search keeps six contracts:

  1. It never throws. A constructor checks its parameters on the host and raises an ArgumentError; linesearch raises nothing.
  2. It returns $α > 0$.
  3. It reports through the code of its LineSearchResult and never logs.
  4. A non-finite or ascending anchor is reported, not searched: NONFINITE and LINESEARCH_FAILED. A stationary anchor, $φ′(0) = 0$, is STALLED. Static is the exception: it reads no anchor and returns its step.
  5. Its number of evaluations does not depend on the scale of the merit.
  6. It returns $α ≤ α_{max}$, for the caller's αmax and for its own.

It never evaluates the merit at $α = 0$: the caller passes $φ(0)$, which is the residual it already has.

source
GeometricSolvers.linesearch — Function
linesearch(ls::LineSearch{R}, lf, step, φ₀::R, α::R, αmax::R = R(Inf))

Run the line search ls along the line function lf from the trial step α, and return a LineSearchResult{R}. φ₀ is the merit at $α = 0$, which the caller has; step is an ExactStep, an InexactStep{R}, a MeasuredSlope or the slope $φ′(0)::R$ itself; αmax is the caller's ceiling on the step. A trial step that is not positive or not finite is replaced by 1, and one below the step floor smallest_step is raised to it.

A non-positive or NaN αmax is a caller error. The search then evaluates nothing and returns LINESEARCH_FAILED with the trial step, bounded by the ceiling of the method.

This is the one entry point: it applies the ceiling, the trial step and the anchor checks, then runs the loop of the method. Each loop runs while it has no result, for at most ls.maxiter trips. Static has no loop.

source
GeometricSolvers.φ — Function
φ(lf, α)

The merit of the line function lf at the step α, $φ(α) = \|r(x + α d)\|^2$, in the real type of α. A line search sees a line function only through this and φ′, and through merit_and_residual and anchor_residual, whose fallbacks call φ and return nothing.

GeometricSolvers.φ′ — Function
φ′(lf, α)

The derivative $dφ/dα$ of the merit of the line function lf at the step α: one Jacobian–vector product.

source
GeometricSolvers.ExactStep — Type
ExactStep()

The step kind of a direction from a fresh Jacobian and an exact linear solve. For the merit $φ = \|r\|^2$ it gives $φ′(0) = -2φ(0)$, so no line search evaluates $φ′(0)$. For $φ(0) > \mathrm{floatmax}(R)/2$ that slope overflows, and the search reports NONFINITE.

source
GeometricSolvers.InexactStep — Type
InexactStep(η)

The step kind of a direction d with the linear residual $\|r + J d\| ≤ η \|r\|$, $0 ≤ η < 1$. It gives only $φ′(0) ≤ -2(1 - η) φ(0)$ (Eisenstat and Walker 1996, (1.2)). Along $α d$ the linear residual is $(1 - α) r + α (r + J d)$, so its bound is $η(α) = |1 - α| + α η$. Backtracking tests $\|r(x + α d)\| ≤ [1 - c_1 (1 - η(α))] \|r\|$ with this $η(α)$, which for $α ≤ 1$ is the update $η ← 1 - θ (1 - η)$ of each backtrack by $θ$, and evaluates no $φ′$. A step with $η(α) ≥ 1$ promises no decrease and is rejected. Bisection and StrongWolfe need the true slope and evaluate $φ′(0)$. The constructor checks nothing, so that solver code can build one in a kernel: a search given an $η$ outside $[0, 1)$ evaluates nothing and returns LINESEARCH_FAILED. Static reads no step kind and returns its step.

source
GeometricSolvers.MeasuredSlope — Type
MeasuredSlope()

The step kind of any other descent direction, such as one from a reused Jacobian: every line search except Static evaluates $φ′(0)$ once. A caller that already has $φ′(0)$ passes the number itself as the step kind, and no search evaluates it.

source
GeometricSolvers.LineSearchResult — Type
LineSearchResult{R <: Real, Q}

The result of one linesearch. It is isbits when the residual is. LineSearchResult{R}(α, φ, code, evaluations) builds one with the residual nothing.

Fields

  • α::R: the step, $0 < α ≤ α_{max}$.
  • φ::R: the merit at α, or NaN if the search did not evaluate it there.
  • code::ReturnCode: SUCCESS for an accepted step that decreases the merit by more than its round-off, and for the step of Static, which evaluates nothing; STALLED for a step that changes the merit by no more than its round-off, or a stationary anchor; NONFINITE for a non-finite anchor; LINESEARCH_FAILED for anything else: an ascending anchor, a spent cap, an increase of the merit, an invalid αmax, or a StrongWolfe step without the curvature condition. φ tells the caller whether the step of a failure still decreases the merit.
  • evaluations::Int32: the evaluations of φ and φ′ together. A StrongWolfe search whose trials share one residual buffer evaluates F once more at a result step that is not its last trial, to restore residual; that evaluation is not counted.
  • residual::Q: the residual at α that gave φ; the residual at $α = 0$ where φ is NaN; nothing for a line function with no residual.
source
GeometricSolvers.roundoff — Function
roundoff(φ₀)

The round-off resolution $τ = 4\,\mathrm{eps}(R)\,|φ(0)|$ of the merit, four units of relative round-off. A step that changes the merit by no more than $τ$ is at the round-off floor of the merit. It is proportional to $|φ(0)|$, not a count of ulps of $φ(0)$, so that it and the step floor smallest_step scale with the merit and do not jump by a factor 2 at a power of two. For a subnormal $φ(0)$, where the product underflows, it is at least four of the smallest subnormals, so it is never 0.

source
GeometricSolvers.smallest_step — Function
smallest_step(d₀, τ)

The step floor $τ / |φ′(0)|$ of every search: below it the decrease that the slope predicts, $α |φ′(0)|$, is smaller than the round-off $τ$, so no trial can show it. It is at least floatmin(R), so that no search tries a step of 0 when the quotient underflows.

source
GeometricSolvers.sufficient_decrease — Function
sufficient_decrease(φα, φ₀, demand, τ)

The Armijo test on the difference, $φ(α) - φ(0) ≤ \min(0, \mathrm{demand} + τ)$, where demand is the negative decrease the test demands and $τ$ the round-off allowance. The difference keeps a demand below one ulp of $φ(0)$, which $φ(0) + \mathrm{demand}$ would round away; the min lets $τ$ lower the demand, never accept an increase. StrongWolfe passes $τ = 0$.

source
GeometricSolvers.classify — Function
classify(φα, φ₀, τ)

The code of an accepted step: SUCCESS for a finite decrease by more than $τ$, STALLED for a change by no more than $τ$, and LINESEARCH_FAILED for an increase by more than $τ$ or a merit that is not finite.

source
GeometricSolvers.backtrack_step — Function
backtrack_step(φ₀, d₀, α, φα, αp, φp, p)

The next trial step after the rejected trial α with merit φα; αp and φp are the trial before it, and αp is NaN on the first backtrack. The model of $φ$ is a quadratic through $φ(0)$, $φ′(0) = d_0$ and $φ(α)$, then a cubic through $φ(α_p)$ as well, both in the merit divided by $|d_0|$. The cubic minimiser is $1 / (b + \sqrt{b^2 + 3a})$ for $b > 0$, which does not cancel as $a → 0$. The result is clamped to $[0.1 α, p α]$; a model without a minimiser gives $p α$, and a merit that is not finite at α gives $0.1 α$.

source
GeometricSolvers.zoom_step — Function
zoom_step(a, φa, da, b, φb, db)

The minimiser of the cubic through the merit φa, φb and its derivative da, db at the two ends a and b of a bracket (Nocedal and Wright, (3.59)), clamped to the inner 80 % of the bracket. The discriminant is scaled by the largest of $|θ|$, $|d_a|$, $|d_b|$, as in Moré and Thuente, so it neither overflows nor depends on the scale of the merit. A cubic without a minimiser gives the middle of the bracket. Without a finite db it is the minimiser of the quadratic through φa, da and φb.

source
GeometricSolvers.LinearMethod — Type
LinearMethod{TF}

The supertype of the linear-solver methods. TF is the factorisation precision: Nothing for the working type of the problem, a real float type, or a PrecisionMarker. It is a type parameter and not a field, because a type stored in a field is not isbits, and a method must enter a kernel.

TF is a real type for a complex problem too: LUFactorization(Float32) factorises a ComplexF64 Jacobian in ComplexF32.

source
GeometricSolvers.compute_forcing — Function
compute_forcing(forcing, k, fnorm, fnorm_prev, η_prev, linres_prev) -> η

The relative tolerance $\eta_k$ of the linear solve of Newton step k, in the real type of the forcing term's constants.

k is the zero-based index of the step, so that k = 0 returns the initial tolerance $\eta_0$ of the term. fnorm is $\|F_k\|$, fnorm_prev is $\|F_{k-1}\|$, η_prev is $\eta_{k-1}$, and linres_prev is the linear residual $\|F_{k-1} + J_{k-1} s_{k-1}\|$ of the last step: the step that a line search accepted on an unrestarted inner solve, and the direction GMRES returned after a restarted one or a DogLeg step. Only EisenstatWalkerChoice1 reads it. A zero, non-finite or NaN fnorm_prev gives $\eta_{\max}$: the ratio of the rule is then undefined, and a residual that vanished ends the solve before the next step reads its tolerance, so the value is a guard and never a step's choice. A non-finite ratio, which a non-finite residual gives, gives $\eta_{\max}$ as well.

max_inner_iterations(solver)

The largest count of GMRES inner iterations of any Newton step of the last solve of solver, a NonlinearSolver whose method is a Newton with GMRES. It is at most the maxiter of the linear method.

GeometricSolvers.GMRESWorkspace — Type
GMRESWorkspace{T, R}

The workspace of one R5 solve: the Krylov basis V of min(restart, n) + 1 columns in the storage of the iterate, the host Hessenberg matrix H after the Givens rotations and H0 before them, the rotation tables cs and sn, the right-hand side g of the least-squares problem, the solution weights y, the weights cg, yN and yb of the matrix-free DogLeg and its reduced work vector sm, the vector slots rr, z, w, u, d and bb of length n, the jvp_eltype slots xT, vT and wT, and the counters of the solve.

f_calls and jvp_calls count the residual evaluations and the Jacobian–vector products of the solve in Int32, gmres_iterations is the inner count of the last Newton step, max_inner the largest inner count of the solve, arnoldi the number of Arnoldi steps of the last inner solve, which the matrix-free DogLeg reads, and step the zero-based index of the current Newton step, which the forcing term reads. last_eta, prev_fnorm, linres and beta are the $\eta_k$, $\|F_{k-1}\|$, linear residual and $\beta_0$ of the last step, linres being that of the step a line search accepted on an unrestarted inner solve and that of the direction otherwise; start!! sets them for the solve and finish!! returns them to NaN, so they are NaN on a state that no start!! saw and on the state that solve!! returned, and a step there fails closed. The counters are mutable, so that a step reports them without rebuilding the workspace.

GMRESInfo

source
GeometricSolvers.gmres_solve! — Function
gmres_solve!(ws::GMRESWorkspace, jvp_op!, P, b, bnorm, tol, maxiter, restart)
    -> (d, GMRESInfo)

Solve J d = b with right-preconditioned GMRES in the workspace ws, and return the direction d = M⁻¹ u in the slot ws.d and a GMRESInfo. jvp_op!(Jv, v) writes the product J v into Jv; P is the right preconditioner; b is the right-hand side and bnorm its norm $\|b\|_2$, which the caller already holds; tol is the relative tolerance, so that the solve stops at $\|b - J d\|_2 \le tol \cdot bnorm$; maxiter caps the inner iterations and restart the iterations between restarts, neither of which may exceed the width the workspace was allocated for.

The Arnoldi process is modified Gram–Schmidt with the conjugated inner product, so a complex iterate is supported and every norm is in real(T). A zero H[j+1, j] is a breakdown: the Krylov space is invariant, and the solve stops there rather than dividing by zero. The residual of the reduced problem is then zero, unless J is singular on that space: the rotated diagonal entry is then zero too, the residual is that of the last entry of the right-hand side, and the solve reports no convergence. A restarted cycle forms its new residual with one more product, b - J M⁻¹ u, so a restart costs one Jacobian–vector product. The least-squares problem is solved from the Givens-rotated Hessenberg matrix, whose diagonal entry is 0 only where the reduced system is singular, and the corresponding weight is then 0.

source
GeometricSolvers.gmres_ir!! — Function
gmres_ir!!(d, ref, state, fac, J, Fx, fnorm) -> (d_ir, ok, ran, linrel, state)

Stage 2 of the mixed-precision remedy chain of a Newton step, GMRES-IR after the LU-IR passes of d have failed: a left-preconditioned GMRES in the working precision T on $\hat{U}^{-1}\hat{L}^{-1}P J \,\delta d = \hat{U}^{-1}\hat{L}^{-1}P r_{\mathrm{lu}}$, with the copy of the factors in TF that promote_lu_factors! writes into the working-precision factor slot, a cap of min(ref.gmres_maxiter, n) inner iterations, and the tolerance ref.gmres_tol on the true linear residual $r_{\mathrm{true}} = -F(x) - J (d + \delta d)$ recomputed in T, which the stage accepts up to ten times its tolerance (Amestoy et al. 2024, p. 13; Kelley 2023, p. 7).

d is the direction the LU-IR passes reached, fac the factorisation in TF they solved with, J the regularised Jacobian the step holds in T, and fnorm the norm $\|F(x)\|$ the tolerance is relative to. It returns the direction (the GMRES-IR one where ok, else d), whether the stage met its bound, whether it ran at all (it does not where the solve keeps no working-precision factor slot and no Krylov basis, where the factor is no LU factorisation, and for any refinement that is not a GMRESRefinement), the relative true residual of the direction it returned, and the state that carries the promoted factor slot it wrote.

source
GeometricSolvers.promote_lu_factors! — Function
promote_lu_factors!(fac_promoted, fac_TF)

Copy the LU factors of fac_TF into fac_promoted, whose element type is the working precision T, and return the promoted factor. L, U and ipiv travel as they are, together with the info and the scale_exponent of the factorisation, so that a solve with fac_promoted gives the step of the factorisation in TF and never factorises the Jacobian again: the copy is what a GMRES-IR stage applies to its Krylov vectors, in T (Amestoy et al. 2024, p. 13). Both factors are dense or device factors of one shape, and the copy allocates nothing.

source
GeometricSolvers.arnoldi_dot — Function
arnoldi_dot(a, b)

The conjugated inner product $\sum_i \overline{a_i} b_i$ of two vectors, in the element type of b: the coefficient of modified Gram–Schmidt, which is real for a real iterate and complex for a complex one. It reduces through a lazy broadcast, so it allocates nothing and indexes no entry.

GeometricSolvers.converged — Function
converged(options::Options{R}, status::SolverStatus{R}, fnorm₀::R, xnorm::R)

The stopping test of Options at status, for a start with residual norm fnorm₀ and an iterate of norm xnorm. GeometricSolvers.rnorm — Function
rnorm(a)

The Euclidean norm $\sqrt{\sum_i |a_i|^2}$ in real(eltype(a)).

Where norm2(a) is finite and at least length(a) * floatmin(R), it is sqrt(norm2(a)), one reduction. Otherwise it scales the entries by $2^{-e}$, where $2^e$ is the power of two of the largest $|a_i|$ (of the largest real or imaginary part for a complex a), so that it neither overflows where the norm is finite nor underflows to zero where the norm is positive. That path takes two more reductions, the largest entry and the sum, and sums in at least Float32. Scaling can round the squares of entries much smaller than the largest to zero, which changes the result in the last bits at most. A NaN entry gives NaN, an Inf entry and no NaN gives Inf. Where real(eltype(a)) is no AbstractFloat, such as an integer or a ForwardDiff.Dual, it is the unscaled sqrt(norm2(a)).

GeometricSolvers.pic_inner_residual — Function
pic_inner_residual(y, c, Δt, Δx, n_cells)

The residual of one particle's Crank–Nicolson orbit step of the one-dimensional implicit electrostatic PIC problem, at the new position and velocity y = (x^{n+1}, v^{n+1}):

\[g_1(y) = \begin{pmatrix} x^{n+1} - x^{n} - \tfrac{\Delta t}{2}(v^{n} + v^{n+1}) \\ v^{n+1} - v^{n} - \tfrac{\Delta t}{2}(E(x^{n}) + E(x^{n+1})) \end{pmatrix},\]

with E(x^{n+1}) gathered from the field the batch shares and E(x^n) the value that the per-system data PIC1DParams holds. c = (E, ps) is the pair that BatchParams passes to system i: the shared field E and that system's PIC1DParams ps.

GeometricSolvers.pic_inner_jacobian — Function
pic_inner_jacobian(y, c, Δt, Δx, n_cells)

The 2 × 2 derivative of pic_inner_residual with respect to y = (x^{n+1}, v^{n+1}),

\[\frac{\partial g_1}{\partial y} = \begin{pmatrix} 1 & -\tfrac{\Delta t}{2} \\ -\tfrac{\Delta t}{2} E'(x^{n+1}) & 1 \end{pmatrix},\]

with E′(x^{n+1}) the gathered field's derivative. It is analytic, so the inner solve takes no derivative of the gather, whose shape function is piecewise polynomial.

GeometricSolvers.deposit_pic_moments! — Function
deposit_pic_moments!(moments, Y, shared, per_system, Δt, Δx, n_cells)

Scatter the moments of the batch Y onto the grid of moments in the canonical order of the batch, and accumulate every sum in the batch's element type typeof(Δt): the number density $\rho_j$, the current $J_j$, the momentum flux $F_j$, and the temperature $T_j = F_j/\rho_j - (J_j/\rho_j)^2$ where $\rho_j > 0$. The order and the precision are fixed by the loop and by the accumulators, so one batch state deposits one set of moments bit for bit, however often it is deposited.

GeometricSolvers.pic_outer_residual! — Function
pic_outer_residual!(F_out, E, moments, E_previous, Δt)

The Ampère residual of one field update of the one-dimensional implicit electrostatic PIC problem, at the new field E,

\[g_2(E) = \frac{E - E^{n}}{\Delta t} + J(E),\]

with J(E) the current that deposit_pic_moments! deposited from the particles advanced under E, and E^n the previous field. Both terms and their sum are evaluated in the batch's element type typeof(Δt), and the value is converted to the element type of F_out: the current is known to the batch's precision only, so a residual summed in the outer precision would report a distance to the root that the batch cannot resolve. That floor of F is a property of F, not of the outer factorisation, so on the problem of make_pic_elimination_problem the outer solve at a tolerance below it ends on a stall and never on a factorisation failure (§1.4).
