Nonlinear solvers

A nonlinear solver holds its algorithmic configuration (linsolve, globalization, jacobian, refinement, regularization and reuse for Newton; damping and globalization for Picard) and nothing about the problem or the iterate. GaussNewton constructs a Newton configured for LeastSquaresProblem (linsolve = QRFactorization(), globalization = Static()). The section The solve interface describes how a method enters a solve.

GeometricSolvers.Newton — Type
Newton(; linsolve = LUFactorization(), globalization = Static(), jacobian = nothing,
         refinement = NoRefinement(), regularization = 0, reuse = nothing,
         forcing = nothing, preconditioner = nothing)

Newton's method for NonlinearProblem, StationarityProblem and, as GaussNewton configures it, for LeastSquaresProblem, with linear solver linsolve (LUFactorization, LDLTFactorization, QRFactorization, SVDFactorization or the matrix-free GMRES), globalization globalization (Static, Backtracking, Bisection, StrongWolfe, the trust region DogLeg or the damped step LevenbergMarquardt), Jacobian selector jacobian, iterative refinement refinement (NoRefinement, Refinement or GMRESRefinement), diagonal regularisation regularization, and factor-reuse period reuse.

Fields

  • linsolve::L: the linear-solver method. A LeastSquaresProblem takes neither LUFactorization nor LDLTFactorization outside the stacked LevenbergMarquardt step. With more residuals than unknowns it takes no factor in a lower precision than the element type of the iterate, because a Gauss–Newton step with such a factor stops off the least-squares point; a factor in the same or a higher precision is taken, and the stacked LevenbergMarquardt step, which reads no factor, takes any. Each refusal raises an ArgumentError where the state is built. A factor in a higher precision on more residuals than unknowns is not promoted to the working precision after a stall: at a nonzero-residual least-squares point $\|F + J d\| \approx \|F\|$, which on a square problem reads as a stall. It is promoted where the factorisation fails.
  • globalization::G: the globalization method. A line search takes its merit at α = 0 from the state, where start!! sets it to norm2(F(x₀)) and each step!! to the merit of the residual it returns. A step!! with a line search therefore takes only the (x, Fx) that the last start!! or step!! on its state returned, as in solve!!. A line-search step on a state that no start!! saw, or that solve!! returned, returns NONFINITE and keeps its iterate, and so does a LevenbergMarquardt step, whose damping parameter that state holds as NaN.
  • jacobian::J: nothing (use prob.J when present, or AutoForwardDiff() otherwise), an AbstractADType, or a custom Jacobian callable: J(x, p), which returns the Jacobian, on a value iterate (a Number or a StaticArray), and J!(J, x, p), which writes it into J, on an array. A Newton with GMRES refuses a callable with an ArgumentError, because a GMRES solve forms no Jacobian matrix. AutoForwardDiff() writes a dense Jacobian only, so with a sparse jacobian_prototype it raises an ArgumentError where the state is built; such a problem takes an analytic J or an AutoSparse back end. Adapting Newton with ToReal (adapt(ToReal{R}(), m)) converts floating-point values captured inside a jacobian closure to R, while a function with no captured floats passes through unchanged.
  • refinement::RF: the refinement setting (NoRefinement, Refinement or GMRESRefinement). A Refinement refines the direction of the system that the factor solves, the regularised $(J + μ I) d = -F$ when μ > 0; a GMRESRefinement runs the same passes and, where they fail on a factorisation below the working precision, a GMRES-IR stage with the promoted factors before the step refactorises in T. A LevenbergMarquardt globalization takes no refinement: a refinement corrects the solve of $J d = -F$, which the damped step does not take, and the constructor raises an ArgumentError. A LeastSquaresProblem takes no refinement either: a refinement drives the linear residual $J d + F$ to zero, which a least-squares step with more residuals than unknowns does not reach, and the refusal raises an ArgumentError where the state is built.
  • regularization::R: non-negative finite diagonal shift $μ ≥ 0$ added as $J + μ I$ before factorisation when μ > 0. A LeastSquaresProblem with more residuals than unknowns takes none, and μ > 0 raises an ArgumentError where the state is built.
  • reuse::K: nothing (K = Nothing, factorise at every step) or Int32(k) (K = Int32, reuse the factor for up to k consecutive steps, refreshing early after a STALLED step and, within the step, after a failed refinement of a Refinement or a GMRESRefinement on a reused factor, which counts one step-rule failure). A line search along a reused factor that fails without a step is retried once, in the same step, from a fresh factor. A DogLeg or LevenbergMarquardt globalization takes no reuse: its model needs the Jacobian of the current iterate, and the constructor raises an ArgumentError.

Keywords of a GMRES linear method

forcing and preconditioner configure the GMRES of linsolve, and a Newton that takes either of them with any other linear method raises an ArgumentError. A Newton with GMRES forms no factor, so it takes no reuse, no Refinement and no LevenbergMarquardt globalization, and a DogLeg needs an unrestarted GMRES without a preconditioner. A JVPFunction in jacobian needs a GMRES, because a factorising method needs a Jacobian matrix. Each refusal is an ArgumentError.

  • forcing: an AbstractForcingTerm that replaces the forcing term of linsolve, and so the relative tolerance of every Newton step's inner solve.
  • preconditioner: the right preconditioner of linsolve, which refresh! is called on once per Newton step and apply_preconditioner! on before every Jacobian-vector product.

GeometricSolvers.Picard — Type
Picard(; damping = 1, globalization = Static())

Damped fixed-point (Picard) iteration for a NonlinearProblem, a StationarityProblem or a LeftPreconditionedProblem, with search direction $d = -\mathrm{damping}\,F(x, p)$ and globalization globalization (Static, Backtracking, Bisection or StrongWolfe).

Fields

  • damping::D: positive finite damping factor $\omega > 0$, stored in floating-point.
  • globalization::G: the globalization method. Any line search uses MeasuredSlope, and takes its merit at α = 0 from the state, where start!! sets it to norm2(F(x₀)) and each step!! to the merit of the residual it returns. A step!! with a line search therefore takes only the (x, Fx) that the last start!! or step!! on its state returned, as in solve!!. A line-search step on a state that no start!! saw, or that solve!! returned, returns NONFINITE and keeps its iterate.

GeometricSolvers.Refinement — Type
Refinement(T = Float64; η = √eps(float(real(T))), maxiter = 5)
Refinement(η, maxiter = 5)

Iterative refinement of the linear direction d in Newton using the existing factor fac and Jacobian-vector products in the working precision T of the problem: a step that factorised at x multiplies by the regularised Jacobian it holds, and a step along a reused factor takes jvp!! at x.

The keyword constructor takes the real type T of η, and the positional one the type of η.

At each inner pass (1 ≤ iter ≤ maxiter), refine!! forms the linear residual r = -F(x) - J(x) d in T, solves fac \ r in the factor precision TF for the correction δd, updates d ← d + δd, and stops as soon as

\[\|F(x) + J(x) d\| \le \max(\eta,\, \sqrt{\varepsilon(R)})\, \|F(x)\|\]

for R = real(T). If a pass fails to strictly decrease ‖F(x) + J(x) d‖ (!(r_curr < r_prev)) or if maxiter passes finish above the threshold, refine!! returns the best direction reached together with failed = true.

Both maxiter ≥ 1 (Int32) and 0 < η < 1 (R <: Real) are validated at construction. Refinement{R} is isbits, and ToReal adapts η to the real type of the iterate.

GeometricSolvers.GMRESRefinement — Type
GMRESRefinement(T = Float64; η = √eps(float(real(T))), maxiter = 5, gmres_maxiter = 30,
                gmres_tol = 1e-6)
GMRESRefinement(η, maxiter = 5, gmres_maxiter = 30, gmres_tol = 1e-6)

The mixed-precision iterative refinement of Newton of Amestoy et al. 2024, their variant SDD, in the five precisions (u_f, u, u_p, u_g, u_r) = (Float32, Float64, Float64, Float64, Float64): the factorisation is in a factorisation precision TF below the working precision T of the iterate, and the linear direction of a step is corrected in T first by Refinement passes with the low-precision factors, then, where those fail, by a preconditioned GMRES in T on a copy of the same factors promoted to T (Kelley 2023, p. 7; Higham and Mary 2022, pp. 374–375).

The keyword constructor takes the real type T of η and of gmres_tol, and the positional one the types of its arguments. Both maxiter ≥ 1 and gmres_maxiter ≥ 1 (Int32) and 0 < η < 1, 0 < gmres_tol < 1 (R <: Real) are validated at construction.

Fields

  • η::R, maxiter::Int32: the tolerance and the pass count of the LU-IR passes, as in Refinement.
  • gmres_maxiter::Int32: the cap on the inner GMRES iterations of one correction, lowered to the number of unknowns of the solve. A correction that reaches the cap without meeting its tolerance is a refinement failure.
  • gmres_tol::R: the relative tolerance of the inner GMRES, on the true linear residual $\|-F(x) - J d\|_2$ of the direction it returns, which the stage recomputes in T and accepts up to ten times, so that the difference between the Arnoldi estimate and the true residual cannot pass a correction that the estimate alone would.

A Newton step whose factorisation is already in T runs the LU-IR passes alone: with no low-precision factor there is no GMRES-IR stage, and the refinement is then a Refinement. A value iterate (Number or StaticArray) has no Krylov basis, so it too runs the LU-IR passes alone, and a step that fails them refactorises in T as with a Refinement.

Mixed-precision refinement

A Newton step whose factorisation runs in a precision TF below the working precision T of the iterate — linsolve = LUFactorization(Float32) on a Float64 problem — corrects its linear direction in T only with refinement = Refinement() or GMRESRefinement(); the default NoRefinement takes the direction of the solve in TF as it is. Refinement is the LU-IR loop of Kelley 2023 (Newton's Method in Three Precisions, doi:10.61208/pjo-2023-030): the factor's TF solve, the residual -F(x) - J d in T, and the correction that solve gives, to the tolerance max(η, √eps(T)) ‖F(x)‖. GMRESRefinement adds the SDD variant of Amestoy et al. 2024 in front of the refactorisation of the Jacobian in T: where the LU-IR passes fail, a left-preconditioned GMRES in T solves for a correction with a copy of the same Float32 factors promoted to T, so the step reaches the accuracy of a factorisation in T without forming one. The remedy chain of a step is therefore LU-IR -> GMRES-IR -> refactorisation in T, and SolverStatus counts each failed stage in step_failures and records a factorisation in T in promoted.

The buffers of a mixed-precision solve are readable after it: stored_factors is the packed L and U of the factorisation in TF, promoted_factors the working-precision copy of it that the GMRES-IR stage promotes (or the factors of the refactorisation, where the step promoted), preconditioned_buffer the slot of the preconditioned product the inner GMRES forms, and linear_residual_buffer the slot of the linear residual -F(x) - J d. scripts/gmres_ir_comparison.jl runs both methods at κ∞ ∈ {1e4, 5e7, 2e8, 5e10}, prints their Newton iteration counts and linear residuals, and recomputes both from the raw output of the solves.

GeometricSolvers.stored_factors — Function
stored_factors(factor)

The n × n storage of the factors of a factorisation, in the element type of the factor: the packed LU (U on and above the diagonal, the multipliers of the unit L below it) of an LUFactorization, which is the storage that promote_lu_factors! copies into the working precision. It is nothing for a solve that holds no factor, and for a factor that is no LU factor: a QR, SVD or LDLᵀ factorisation has no GMRES-IR stage that promotes it.

source
stored_factors(solver)

The factors of the factorisation that the last step of solver took, in the factorisation precision TF: stored_factors of the factor of the state, the packed L and U of an LUFactorization with its ipiv in the factor itself. It is nothing for a solve that holds no factor — a matrix-free GMRES solve, and a value iterate whose factor no step stored — and for a factorisation that is no LU factorisation. stored_factors(state) reads the state that init_state returned instead.

source
GeometricSolvers.promoted_factors — Function
promoted_factors(solver)

The factors of the working-precision copy of stored_factors that a GMRESRefinement promotes, in the element type of the iterate T: T.(stored_factors(solver)) while the GMRES-IR stage that promoted them is the one that holds them, and the refactorised factors of the Jacobian where the step promoted to T instead. The storage belongs to the state, and init leaves it zeroed, so a read before the first promotion reads zeros. It is nothing for a solve that keeps no working-precision factor slot: a factorisation already in T, a value iterate, and a matrix-free GMRES solve; and for a factorisation that is no LU factorisation.

source
GeometricSolvers.preconditioned_buffer — Function
preconditioned_buffer(solver)

The buffer of the preconditioned product $\hat{U}^{-1} \hat{L}^{-1} P (J v)$ that the GMRES-IR stage of a GMRESRefinement forms for each Krylov vector v, in the working precision T, or nothing for a solve that forms none. preconditioned_buffer(state) reads the state that init_state returned instead.

source
GeometricSolvers.linear_residual_buffer — Function
linear_residual_buffer(solver)

The buffer of the linear residual $r = -F(x) - J d$ of the last step of solver, in the working precision T, which the defect-correction passes and the GMRES-IR stage reuse. It is nothing for a solve that refines nothing, and for a value iterate, whose storage holds no buffer. It is not the slot of F(x₀) that residual_buffer names. linear_residual_buffer(state) reads the state that init_state returned instead.
