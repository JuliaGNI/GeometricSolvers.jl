Combinators and preconditioning

Combinators

Additive, Multiplicative, Repeat, Switch, Anderson and Broyden compose nonlinear methods through the same init_state, start!!, step!! and finish!! interface as Newton and Picard, so a combinator runs in R1, R2 and R3 alike. Additive combines member steps from the same iterate with OptimalWeights or FixedWeights, Multiplicative and Repeat thread (x, F(x)) sequentially across sub-steps while sync_merit updates any active line-search baseline merit, Switch transitions permanently from first to second once $\|F(x)\| \le \text{threshold} \cdot \|F(x_0)\|$, Anderson accelerates its member with filtered Type-II Anderson mixing, Tikhonov regularisation, restarts and best-iterate restoration, and Broyden accelerates its member over the same shared AndersonHistory, filters and safeguards by solving the lower-triangular Type-II Broyden multisecant equations by forward substitution. A combinator has no implicit differentiation: solve with a combinator method raises an ArgumentError for a ForwardDiff.Dual in x₀ or p.

Fallback composes whole solves instead of steps: it runs solve!! with each member in turn, each from x₀, and stops at the first member that returns SUCCESS; fallback_member reads the index of the member whose result a solve returned.

GeometricSolvers.Additive — Type
Additive(m₁, m₂, ...; weights = OptimalWeights())
Additive((m₁, m₂, ...), weights::Union{OptimalWeights, FixedWeights} = OptimalWeights())

Parallel nonlinear combinator that runs one step of each member from the same iterate (x, F(x)) to obtain candidates $(x_i, F(x_i))$ and forms $x_+ = x + \sum_{i=1}^m w_i (x_i - x)$ using OptimalWeights or FixedWeights. Under OptimalWeights, a rank-deficient Gram matrix drops the collinear candidate directions and solves the weights over the ones kept, a one-weight secant step when one survives; a trial iterate that violates the PETSc safeguard is replaced by the candidate with the smallest residual norm. Each rule counts one failure in step_failures, and a step on which both fire counts one.

A member whose step fails hard (SINGULAR, NONFINITE, or LINESEARCH_FAILED with a zero step) is left out of the combination: OptimalWeights solves for the weights of the members kept, and FixedWeights rescales the weights of the members kept to the sum of all weights. The step fails, with the code of the first member that failed, when every member fails, or when the fixed weights of the members kept sum to zero. The step is STALLED when every member step is.

The tuple form takes the weight rule as its second positional argument: a weights keyword after a tuple makes the tuple a single member.

GeometricSolvers.OptimalWeights — Type
OptimalWeights(ρ = 1.0)
OptimalWeights(; ρ = 1.0)

Secant least-squares weight rule for Additive. Minimises the linearised model residual $\|F(x) + \sum_i w_i (F(x_i) - F(x))\|_2$ over real weights $w_i \in \mathbb{R}$, drops rank-deficient candidate directions in favour of the candidate with the smaller residual norm, and falls back to the best candidate when $\sum_i |w_i| < 0.1$, when $\|F(x_+)\| > \rho \min_i \|F(x_i)\|$, or when $F(x_+)$ is not finite.

Multiplicative((m₁, m₂, ...))

Sequential nonlinear combinator (composite step $G_m \circ \cdots \circ G_1$) that threads (x, F(x)) through m₁, m₂, ... in order within a single outer solver iteration. GeometricSolvers.Switch — Type
Switch(first, second; threshold = 1e-2)
Switch(first, second, threshold)

Two-stage nonlinear combinator that runs first while $\|F(x)\| > \text{threshold} \cdot \|F(x_0)\|$ and latches permanently to second for the remainder of the solve once $\|F(x)\| \le \text{threshold} \cdot \|F(x_0)\|$. Calling step!! on a state that has not been initialised by start!! (!isfinite(state.fnorm₀)) fails closed with NONFINITE and a zero step norm.

GeometricSolvers.Fallback — Type
Fallback(m₁, m₂, ...)
Fallback((m₁, m₂, ...))

Whole-solve combinator that runs solve!! with each member in turn and stops at the first member that returns SUCCESS. Every member starts from x₀, with the full Options of the solve and its own state, which start!! resets as for a solve with the member alone; solve!! copies an array x₀ into the state before the first member and back into the iterate before each later one, so each member's result is the result of its own solve from x₀. Every code but SUCCESS moves on to the next member, and an exception that a member throws is not caught.

The SolverStatus is that of the member that succeeded, or of the last member when none did, with iterations and step_failures summed over the members that ran (each saturated at typemax(Int32)), promoted set when any of them set it, and the call counts f_calls and jvp_calls 0. The state that solve!! returns holds the index of that member, which GeometricSolvers.fallback_member reads.

Fallback needs at least one member, and raises an ArgumentError with none. It has no step!!, so it is a method of its own and not a member of a step-level combinator such as Switch. Like every combinator, it refuses a ForwardDiff.Dual in x₀ or p in solve and a LeastSquaresProblem in init_state.

fallback_member(state::FallbackState)

The index of the member of a Fallback whose result the last solve!! on state returned: the member that succeeded, or the last member when none did; 0 for a state that no solve returned.

GeometricSolvers.Anderson — Type
Anderson(member, ::Val{m};
         c_s = 0.2, κ_bar = nothing, restart_factor = 10.0,
         M_alpha = 25.0, safeguard_cos = nothing, grow_depth = false)
Anderson(::Val{m}; damping = 1, kwargs...)
Anderson(member, m::Integer = 4; kwargs...)
Anderson(m::Integer = 4; damping = 1, kwargs...)

Type-II Anderson acceleration of history depth m wrapping an inner nonlinear method member (Picard, Newton, or a combinator). At each outer iteration, Anderson runs one step of member from (x, Fx) to obtain the candidate x_m and correction w_k = x_m - x, updates the history of consecutive iterate differences Δx_j and correction differences Δw_j, filters the history by the length and angle filters of Pollock and Rebholz (2023) from the Gram matrix G_{ij} = Re⟨Δw_i, Δw_j⟩, solves the eps(R)-regularised normal equations (G_K + λI) γ = b_K with b_i = Re⟨Δw_i, w_k⟩, and forms the accelerated iterate x₊ = x_m - ∑_j γ_j (Δx_{K[j]} + Δw_{K[j]}).

In R1 (StaticVector or Number), m must satisfy 1 <= m <= 4, and the state is isbits for an SVector or Number iterate. In R3 (Array or AbstractGPUArray), any m >= 1 is supported with preallocated n × m difference matrices, and step!! on an Array allocates nothing. When a solve ends with a code other than SUCCESS, finish!! restores the iterate with the smallest residual norm ‖F(x)‖ seen during the solve. A step is STALLED when the step of member is.

The constructors without a member wrap Picard(; damping), so Anderson() wraps the undamped Picard().

Keywords:

  • c_s: angle-filter threshold in (0, 1); a history column is kept only if its component orthogonal to the kept columns has squared norm ≥ c_s² G_jj.
  • κ_bar: bound of the length filter; nothing selects 1 / sqrt(eps(R)) for the real element type R of the iterate.
  • restart_factor (≥ 3): the history is cleared when ‖F‖ exceeds restart_factor times the smallest residual norm seen.
  • M_alpha (≥ 1): bound on ∑_j |α_j| for the affine weights α_j of the member candidates g_{k-j} that x₊ combines, also after a filter has dropped a history column; a step whose weights exceed it, are not finite, or increase the residual of the linear model takes the step of member and counts one failure.
  • safeguard_cos: when set, the history is cleared if the cosine between consecutive corrections w_k exceeds it in modulus.
  • grow_depth: when true, the depth is capped at ceil(-log10(‖w_k‖)) clamped to 1:m, so the cap grows as the corrections shrink.

References

  • S. Pollock and L. G. Rebholz (2023). Filtering for Anderson acceleration. SIAM Journal on Scientific Computing 45(4), A1571–A1590. doi:10.1137/22M1536741

GeometricSolvers.Broyden — Type
Broyden(member, ::Val{m};
        c_s = 0.2, κ_bar = nothing, restart_factor = 10.0,
        M_alpha = 25.0, safeguard_cos = nothing, grow_depth = false)
Broyden(::Val{m}; damping = 0.5, kwargs...)
Broyden(member, m::Integer = 4; kwargs...)
Broyden(m::Integer = 4; damping = 0.5, kwargs...)

Type-II Broyden (bad Broyden) multisecant acceleration of history depth m wrapping an inner nonlinear method member (Picard, Newton, or a combinator). Shares the difference history, length and angle filters of Pollock and Rebholz (2023), extrapolation safeguards, restarts, and best-iterate restoration of Anderson, differing in the weight solve: instead of the full Gram normal equations, Broyden solves the lower-triangular multisecant system (L_G + λI) γ = b_K by forward substitution, where (L_G)_{c,r} = Re⟨Δw_{K[c]}, Δw_{K[r]}⟩ for r <= c and λ = eps(R) * tr(G_K) / p. The kept columns K are in increasing age, newest first; in this order, and for λ = 0, the weights are those of the sequential rank-one Type-II Broyden updates of group size one (Fang and Saad, 2009), applied oldest column first.

In R1 (StaticVector or Number), m must satisfy 1 <= m <= 4, and the state is isbits for an SVector or Number iterate. In R3 (Array or AbstractGPUArray), any m >= 1 is supported with preallocated n × m difference matrices, and step!! on an Array allocates nothing.

Keywords are identical to Anderson. The constructors without a member wrap Picard(; damping) with damping = 0.5 by default, so Broyden() wraps a damped Picard, while Anderson() wraps the undamped Picard().

References

  • S. Pollock and L. G. Rebholz (2023). Filtering for Anderson acceleration. SIAM Journal on Scientific Computing 45(4), A1571–A1590. doi:10.1137/22M1536741

GeometricSolvers.AndersonHistory — Type
AndersonHistory{m, X, DX, DW, A}

Immutable view of the difference history stored in an AndersonState{m} for Anderson and Broyden, returned by state.history.

Fields:

  • x_prev: previous outer iterate x_{k-1}.
  • w_prev: previous member correction w_{k-1} = g(x_{k-1}) - x_{k-1}.
  • ΔX: stored iterate differences Δx_j = x_{k-a_j+1} - x_{k-a_j} (NTuple{m} in R1, n × m matrix in R3).
  • ΔW: stored correction differences Δw_j = w_{k-a_j+1} - w_{k-a_j} (NTuple{m} in R1, n × m matrix in R3).
  • ages: column ages (NTuple{m, Int32} in R1, Vector{Int32} in R3).
  • depth: number of active columns currently stored in ΔX and ΔW.
  • current_depth: active depth cap (1:m) after the most recent step.
  • has_prev: true once x_prev and w_prev hold a previous step.

Nonlinear preconditioning

LeftPreconditioned(outer, inner) runs outer on the residual $r^\ell(y) = y - N(y)$ of one step of inner instead of on F, so every trial point of its globalization costs one inner step and every merit value it reads is $\|r^\ell\|_2^2$. With the inner method a one-level RAS map over a BlockPartition it is RASPEN, LeftPreconditioned(Newton(), RAS(partition)), whose Jacobian is the exact form from the block factors of the last sweep; RASPEN needs converged local solves. Multiplicative(RAS(partition), Newton()) is NKS-RAS, the same map followed by one Newton step. A RAS sweep restricts each subdomain, solves each block with the package's own factor, and prolongates through the owner sets only, so each index of 1:n is written once and the sweep calls the global residual no times; ras_counts reports the counters of its last solve. A problem with block residuals supplies the block functions, and a block without a Jacobian is differentiated by AutoForwardDiff().

GeometricSolvers.LeftPreconditioned — Type
LeftPreconditioned(outer, inner)

The left-preconditioned method of a NonlinearProblem: the method outer runs on the residual $r^\ell(y) = y - N(y)$ of the inner map $N$, one step!! of inner from (y, F(y)), instead of on F itself. Every trial point of outer's globalization therefore costs one inner step, and every merit value it reads is $\|r^\ell\|_2^2$. The zeros of $r^\ell$ are the fixed points of $N$.

LeftPreconditioned(Newton(), RAS(partition)) is RASPEN: the merit is on the restricted additive Schwarz map, and the Jacobian of $r^\ell$ is the exact form of raspen_jvp! built from the block factors of the last sweep (Dolean:2016, eq. 3.17). RASPEN needs converged local solves: a RAS with a positive tolerance whose local solve does not converge returns MAXITERS, and a LeftPreconditioned step that meets it, at its iterate or at the trial point where its outer step reports NONFINITE, returns MAXITERS too, which ends the solve. A RAS with a balance_threshold is refused at init_state with an ArgumentError, because a skipped sweep returns its input and so reads as a zero of $r^\ell$ at a point that is not a root. A Newton with GMRES as outer is refused at init_state with an ArgumentError, because it solves a NonlinearProblem and outer solves $r^\ell$; as inner it is taken. outer may be a combinator, such as Repeat or Multiplicative, whose members step on $r^\ell$; with a RAS inner, every member of an Additive after the first costs one more sweep, at the iterate, because the RASPEN Jacobian reads the block factors of the last sweep. A Deflated problem is refused at init_state with an ArgumentError, because its stopping test reads the deflation factor from a Newton state. With an inner other than a RAS the derivative of $r^\ell$ is a central difference, one inner step at each of $x \pm h v$, which prepare_ad prepares at init_state whatever its globalization reads. With a RAS inner that preparation is the RASPEN form, so every sweep forms the block factor at the local iterate it returns even for a globalization that reads no slope: measured on the 5-block P8 problem at one inner iteration per block, a LeftPreconditioned(Picard(), RAS) under Static makes 10 block-Jacobian calls per sweep against plain RAS's 5.

The solve!! status of a LeftPreconditioned solve is the one of the loop: its fnorm is $\|F(x)\|$ of the global residual at the returned iterate, and its convergence tests apply to that residual. init_state raises the ArgumentError of an inner RAS for a problem without block residuals.

LeftPreconditionedAD

The AD preparation of a LeftPreconditioned method whose inner state is not a RASState: the iterate and residual buffers of the two points of a central difference, and the direction buffer that seeds one column at a time. jvp!! evaluates $r^\ell$ at $x \pm h v$ and forms $(r^\ell(x + hv) - r^\ell(x - hv)) / 2h$, and jacobian!! takes one column per call of it.

GeometricSolvers.RAS — Type
RAS(partition::BlockPartition; max_iterations = 1, rtol = 0, atol = 0,
    balance_threshold = nothing)

The restricted additive Schwarz map of one-level nonlinear preconditioning, as a nonlinear solver method of NonlinearProblem with block residuals: one step!! restricts the iterate to each subdomain, takes up to max_iterations local Newton steps with that block's own factor, and prolongates through the owner sets only, so every index is written once. A sweep evaluates each block residual once per inner iteration and calls the global residual no times; the step then evaluates the global residual once at the swept iterate and returns it, so a member of Multiplicative passes the next member a residual of the iterate that the sweep reached. LeftPreconditioned(Newton(), RAS(partition)) is RASPEN and Multiplicative(RAS(partition), Newton()) is NKS-RAS.

An inner iteration of block i stops before its linear solve when the block residual norm is at most atol + rtol * ‖f_i⁰‖, with f_i⁰ the block's residual at its first inner iteration. With a positive tolerance (atol > 0 or rtol > 0), a local solve is also converged at its residual floor, the bound of the rounding error of its residual: a block residual norm of at most $n_i \varepsilon \|J_i\|_F \|x_i\|$ ends it, with $n_i$ the block size, $J_i$ the block Jacobian of its last Newton step, $\|\cdot\|_F$ the Frobenius norm and $\varepsilon$ the eps of the element type. A local solve that takes all max_iterations steps evaluates its block residual once more, and where that norm is above the tolerance and above the floor, the local solve has not converged: the step returns the iterate unchanged with MAXITERS, which ends the solve, and ras_counts names the block in failed_block. With atol = rtol = 0 every local solve takes max_iterations steps and makes no claim of convergence. With balance_threshold = ρ the step returns the iterate unchanged, as a SUCCESS of zero norm, when $\max_i \|R_i F(x)\| \le \rho \|F(x)\|$ (CaiLi:2011); the block residuals cost one call per block in that test, and the global residual costs none. LeftPreconditioned refuses a RAS with a balance_threshold.

The counters of the last start!! are read with ras_counts. A problem without block residuals, a partition whose block count or index count differs from the problem's, and an iterate that is not a vector raise an ArgumentError at init_state; the partition's validation raises one at construction. A jacobian_prototype sizes the global Jacobian only: the block factors are dense. Only a RASPEN product reads the global Jacobian, so on a sparse jacobian_prototype without an analytic J a sweep, and a Picard outer under Static, solve without one, and a reader of the RASPEN product — a Newton outer, or a Picard outer with a line search — raises an ArgumentError at init_state: the ForwardDiff Jacobian of the global residual writes a dense Jacobian only.

GeometricSolvers.RASState — Type
RASState

The state of a RAS method: the workspace of every block, the factors of the block Jacobians, which raspen_jvp! and raspen_jacobian! read, the global Jacobian buffer and its preparation — nothing where the problem has its own J, and AutoForwardDiff() on F where it has none; both nothing on a sparse jacobian_prototype without J, where no global Jacobian is built — the composite iterate that a RASPEN Jacobian product forms per block, and the counters that ras_counts reports. Every block factor is re-formed in every inner iteration, and once more at the local iterate that the sweep returns where the block factors feed a RASPEN preparation, which is the factor at the local solution. A factor that no sweep has written fails closed: the product raises an ArgumentError before it reads one.

GeometricSolvers.BlockPartition — Type
BlockPartition(subdomains, owners)
BlockPartition(n, nblocks; overlap = 1)

The index sets of a one-level Schwarz method over 1:n: one subdomain S_i per block, which holds the index set of the local solve, and one owner set S̃_i ⊆ S_i per block, which holds the indices that the block writes back. The owner sets are pairwise disjoint and cover 1:n exactly, so a RAS sweep writes each index once and the map is the restricted form. A subdomain is non-empty and repeats no index, and every index is in 1:n, with n the largest index of any subdomain; any other input raises an ArgumentError. The field local_owners[i] holds the positions of owners[i] in subdomains[i], so that subdomains[i][local_owners[i]] == owners[i].

BlockPartition(n, nblocks; overlap = 1) splits 1:n into nblocks contiguous owner sets of equal or nearly equal size, and extends each into its subdomain by overlap indices on each side, clipped to 1:n. overlap = 0 gives subdomains == owners, which is block Jacobi; n < 1, nblocks < 1, nblocks > n and overlap < 0 raise an ArgumentError.

GeometricSolvers.ras_sweep!! — Function
ras_sweep!!(state, m::RAS, prob, x, p)

Run one restricted additive Schwarz sweep from the iterate x, overwrite x with the swept iterate, and return it. The sweep restricts each subdomain, evaluates that block's residual once per inner iteration, solves the block system with the block's own factor, and prolongates through the owner sets. It calls the global residual no times. A block factor that reports a zero pivot, a block residual with a non-finite entry, and a local solve with a positive tolerance that does not converge leave x unchanged; the step!! of RAS reports them as SINGULAR, NONFINITE and MAXITERS.

GeometricSolvers.ras_prolongate! — Function
ras_prolongate!(dest, x_locals, partition)

Write each block's local iterate back into dest at that block's owner set, dest[owners[i][k]] = x_locals[i][local_owners[i][k]], for the host index sets of partition. Each index of 1:n is written once, because the owner sets of a BlockPartition are disjoint and cover 1:n. GeometricSolvers.ras_counts — Function
ras_counts(state)

The counters of the last solve of a RAS state, as a named tuple:

  • sweeps: the sweeps run.
  • parallel_block_solves, parallel_inner_iterations, inner_iterations: the block solves of the parallel schedule — one per inner iteration of the slowest block of each sweep, summed over the sweeps — and, where a RASPEN preparation reads the block factors of the state, one more per sweep for the block Jacobian that each block forms at the local iterate its sweep returns.
  • total_inner_iterations, block_solves: every block solve, summed over the blocks and the sweeps, with the same one more per block on such a state.
  • failed_block: the block whose local solve did not converge in the last sweep, which made the step return MAXITERS, or 0.

start!! resets them, so a second solve! on one solver reports its own solve. A state of LeftPreconditioned with an inner RAS, and a state of Multiplicative with a RAS member, report that member's counters.

GeometricSolvers.raspen_jvp! — Function
raspen_jvp!(Jv, state, prob, x, v, p)

The Jacobian-vector product of the left-preconditioned residual $r^\ell(y) = y - N(y)$ of the exact RASPEN Jacobian, $J_{r^\ell}(x) v = \sum_{i=1}^M \tilde{R}_i^\top (R_i J(u^{(i)}) P_i)^{-1} R_i J(u^{(i)}) v$ (Dolean:2016, eq. 3.17), with the block factors that the last sweep of state formed and $u^{(i)}$ the iterate x with the local solve x_locals[i] of block i written over its subdomain $S_i$. Per block it evaluates the global Jacobian at $u^{(i)}$, keeps the rows of $S_i$, multiplies them by v, solves with that block's factor, and prolongates through the owner set. The global Jacobian is the problem's own J where it has one, so a residual that takes no ForwardDiff.Dual serves RASPEN, and AutoForwardDiff() on F where it has none. Jv is overwritten and returned. A state that no complete sweep formed has no block factor to read, so it raises an ArgumentError.

source
GeometricSolvers.raspen_jacobian! — Function
raspen_jacobian!(J, state, prob, x, p)

The Jacobian of the left-preconditioned residual $r^\ell$ at x of the exact RASPEN form of raspen_jvp!. Per block it evaluates the global Jacobian once, at $u^{(i)}$, and solves all columns of its subdomain rows with that block's one factor, so a call takes one global Jacobian per block. It overwrites J and returns it. A state that no complete sweep formed raises an ArgumentError.
